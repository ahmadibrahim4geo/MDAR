## 1. الهدف والمقارنة المعمارية للمحركات (Engine Architectural Evaluation)

وفق خطة التطوير الرئيسية، تم تقييم مسارات التحويل الجيوديسي لتشغيل منصة **مدار – MِDAR** محلياً بالكامل (100% Offline / Client-Side) في المتصفح دون الاعتماد على خوادم خارجية أو اشتراكات مدفوعة:

### 1.1 مقارنة الخيارات البرمجية:
1. **المحرك التحليلي المخصص (Custom Analytical Engine - الوضع الموروث):**
   - *المزايا:* خفيف الوزن وصغير الحجم، ينفذ تحويل Molodensky-Badekas المكون من 10 معاملات للمرجع المصري بدقة تامة.
   - *العيوب:* انقطاع متسلسلة تايلور لمسقط ميركاتور المستعرض عند الرتبة السادسة أظهر انحرافاً قدره $2.23\text{ mm}$ في الـ Roundtrip، وصعوبة كتابة وصيانة جميع مساقط الدول العربية الـ 22 يدوياً (LCC, Cassini-Soldner, Stereographic).
2. **محرك Proj4js المتخصص (Lightweight Client-Side Engine):**
   - *المزايا:* مكتبة قياسية مفتوحة المصدر (MIT)، مجربة في Leaflet وOpenLayers وMapLibre، تدعم جميع مساقط OGC/EPSG (Transverse Mercator, UTM, Cassini-Soldner, Lambert Conformal Conic, Web Mercator)، وتستخدم خوارزمية Clenshaw summation لمتسلسلات المساقط بدقة متناهية (Residual صفر).
   - *العيوب:* لا تدعم في صيغة `+towgs84` البسيطة معاملات Molodensky-Badekas العشرية مع نقطة الدوران الأصلية ($pX, pY, pZ$).
3. **محرك GDAL / PROJ WASM (عبر gdal3.js / emscripten):**
   - *المزايا:* تشغيل مكتبة PROJ وGDAL الكاملة وقراءة شبكات التصحيح (Grid Shift files).
   - *العيوب الحالية:* حجم الحزمة كبير جداً ($>25\text{ MB}$ لملف WASM وقاعدة proj.db)، وبطء أولي في التحميل على أجهزة المحمول والمتصفحات ذات الذاكرة المحدودة.

## 2. الهندسة المعمارية المعتمدة لمنصة مدار (Dual-Engine Hybrid Architecture)

لتحقيق أقصى درجات الدقة والسرعة دون أي تضحية بالمعايير العلمية، تم اعتماد **الهندسة الهجينة ثنائية المسار (Dual-Engine Architecture)**:

```
                          ┌─────────────────────────────┐
                          │     إحداثيات الإدخال (X, Y) │
                          └──────────────┬──────────────┘
                                         │
                   ┌─────────────────────┴─────────────────────┐
                   │                                           │
         [نظام مصري / Egypt 1907]                    [نظم عالمية / عربية / UTM]
                   │                                           │
         ┌─────────┴─────────┐                       ┌─────────┴─────────┐
         │ Molodensky-Badekas│                       │ Proj4js Clenshaw  │
         │     EPSG:7697     │                       │ TM / LCC / Cassini│
         │  (الدقة: 1.2 متر) │                       │  (الدقة: < 1 ملم) │
         └─────────┬─────────┘                       └─────────┬─────────┘
                   │                                           │
                   └─────────────────────┬─────────────────────┘
                                         │
                          ┌──────────────┴──────────────┐
                          │ مصفوفة النتائج + Provenance  │
                          │   (إحداثيات + كود العملية)   │
                          └─────────────────────────────┘
```

1. **مسار المرجع المصري (Egypt 1907):**
   - تطبيق عملية `EPSG:7697` الرسمية باستخدام نموذج Molodensky–Badekas المكون من 10 معاملات (3 إزاحات، 3 دورانات، معامل مقياس، وإحداثيات مركز الدوران).
   - دمج حسابات المسقط المستعرض عبر Proj4js لضمان بقاء خطأ التحويل العكسي أقل من $1\text{ mm}$.
   - توثيق دقة العملية الرسمية ($1.2\text{ m}$) وإضافة تنبيهات واضحة للمستخدم بعدم مطابقة الارتفاع البيضاوي بالارتفاع الأورثومتري.

2. **مسار النظم العالمية والعربية (UTM, Arab National Grids, Web Mercator):**
   - استخدام محرك `proj4` المدمج مع تعريفات دقيقة ومرقمة لجميع مراجع دول الوطن العربي الـ 22.
   - استخدام مصفوفات الدوران 7-معاملات و3-معاملات المعتمدة من مساحات الدول الوطنية وEPSG Registry.
   - كشف أي عملية تحويل تقريبية للمستخدم صراحة وتوثيقها بـ `APPROXIMATE_OPERATION_WARNING`.
